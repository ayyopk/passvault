# v2.1 Bug 與安全檢查

日期：2026-10-12。來源 SHA-256：`9ED9FA9928240DEC7F7B33E475C711B3A3212919DE87D632F2B53EBB466251A1`。
參考程式沒有內嵌密碼庫；所有實際操作只用虛構資料。

## 已確認並修正

| 問題 | 影響與原程式行為 | 修正與驗證 |
| --- | --- | --- |
| 高：匯出期間修改被覆蓋 | encrypt await 期間仍可編輯，之後 vault=clean 會把較新的輸入覆蓋成舊快照 | 保持目前 vault，以獨立快照匯出；確認時只清除對應已儲存項目的新資料提示，後續修改保留 dirty。原程式實測失敗，修正後實測通過 |
| 高：手機寬畫面出現編輯看板 | UA 即使判定唯讀，CSS min-width 仍顯示可編輯看板與功能按鈕；桌面 UA 的 Apple 裝置也可能誤判 | 依裝置資訊套用原手機樣式，手機不建立電腦帳密卡片。1100px、iPad/iPhone 桌面 UA 與唯讀入口測試通過 |
| 高：鎖定只隱藏明文 | 輸入欄位及詳細 DOM 保留解密內容；主密碼仍在 login input，未完成的非同步工作可能回填 | 清除 DOM 與欄位，使用 session 與密碼庫物件核對非同步結果。原程式明文殘留實測失敗，修正後及解密／匯出競態測試通過 |
| 中：TXT 破壞密碼空白 | 每行 trim() 並移除空行，密碼首尾空白被截掉 | 保留帳號、密碼與備註的原文字，標題單獨 trim。原程式虛構空白密碼實測失敗，修正後逐字核對通過 |
| 高：匯入完整性不足 | 不驗證分類 ID 重複、schema、欄位型別與參照；未知分類默默移到未分類；未排序舊分類忽略；額外 url 等欄位丟棄 | 開啟前驗證完整結構，保留未排序分类、孤立舊帳密及額外欄位；損毀索引整體拒絕。核心與瀏覽器拒絕及完整性測試通過 |
| 中：匯出成功判定過早 | 點擊 download 就清 dirty、清黃色，使用者取消或未儲存仍可能丟失修改 | 下載後用既有 modal 確認儲存；取消／失敗保留提示。真實 download 事件、加密失敗及取消測試通過 |
| 中：背景事件覆蓋不足 | 只有 visibilitychange 回前景判斷，pagehide 沒記期限，閾值用 >30000 | 單一背景期限与計時器；回前景檢查 >=30000。短暫 20 秒、恰 30 秒及計時器不執行的情境通過 |
| 中：搜尋範圍不一致 | 未分類不搜尋分類名稱；單獨檢視資料夾會限制跨分類結果 | 共用包含判斷，覆蓋全部四欄位。逐字 tw/twi/twitter、銀、未分類及單獨檢視情境通過 |
| 中：同秒檔名及等待收尾 | 同秒檔名相同；主密碼背景取消的 Promise 無法結束 | 檔名加入毫秒、序號、隨機尾碼；取消、鎖定會結束等待。重複匯出及再試匯出通過 |
| 安全強化：HTML 解析與错误片段 | DOMParser 處理外來 HTML，有載入資源風險；JSON 錯誤可能帶原始內容 | 用未掛到文件的 template 惰性解析，只讀唯一資料節點；錯誤文字固定。含脚本、圖片及帳密樣式的損毀 JSON 測試通過，無外部請求 |

## 未重現的歷史問題

使用者這次提供的原始 v2.1 在虛構資料實測中，完成新增會清除 draft，tw→twi 搜尋也保持 Twitter 結果。這兩處沒有作多餘修正；已納入正式回歸測試，包括空庫設定主密碼後直接匯出。

## 檢查範圍與待驗收

已讀取全部 v2.1 程式，審查 crypto、信任邊界、DOM、拖曳、檔案處理與狀態生命周期，並以實際瀏覽器驗證。PC 布局保持原提供版，初始截圖逐像素一致。

沒有測試使用者真實帳密、操作其 iCloud 或部署正式網站。WebKit 裝置模擬不能替代真實 iPhone Safari；背景暫停、iCloud 選檔、OS 剪貼簿與下載的實際儲存仍須裝置驗收。TXT 的空行分段格式不能表達任意多行密碼；此類資料請使用加密密碼庫。
